# 할 일 요구사항

상태: `Proposed`

## 사용자 요구사항

### 할 일 화면과 캘린더

- 할 일 화면은 월 이동, 날짜 선택, 선택 날짜의 할 일 목록과 할 일 추가 진입점을 제공해야 합니다.
- 최초 진입 시 오늘 날짜를 선택하고, 선택 날짜와 오늘 날짜를 시각적으로 구분해야 합니다.
- 사용자는 이전·다음 버튼 또는 스와이프로 월을 변경할 수 있어야 합니다.
- 사용자가 월을 변경하거나 날짜를 선택하면 해당 날짜의 할 일 목록을 표시해야 합니다.
- 선택 날짜에 할 일이 없으면 빈 상태 문구와 할 일 추가 버튼을 표시해야 합니다.
- 월 단위 캘린더는 아래로 스크롤하면 선택 날짜가 포함된 주 단위로 접혀 목록 공간을 확보해야 합니다.
- 사용자가 목록 최상단에서 위로 스크롤하면 월 단위 캘린더를 다시 펼쳐야 합니다.
- 접힌 캘린더에서도 선택 날짜를 확인하고 월을 변경할 수 있어야 합니다.
- 캘린더는 한국어로 표시하고 한 주는 일요일부터 시작해야 합니다.

### 할 일 조회와 관리

- 선택 날짜의 할 일을 카테고리와 함께 표시해야 합니다.
- 카테고리와 각 카테고리 안의 할 일은 사용자가 저장한 순서대로 표시해야 합니다.
- 사용자는 같은 카테고리 안에서 할 일을 드래그해 순서를 변경할 수 있어야 하며, 변경된 순서는 즉시 저장해야 합니다.
- 할 일 순서 저장에 실패하면 이전 순서로 복원하고 재시도 방법을 안내해야 합니다.
- 사용자가 할 일을 선택하면 완료 상태로 변경하고 완료 결과를 즉시 표시해야 합니다.
- 완료된 할 일을 다시 선택하면 미완료 상태로 변경한 결과를 즉시 표시해야 합니다.
- 사용자는 할 일의 상세 영역 또는 메뉴에서 해당 할 일을 수정하거나 삭제할 수 있어야 합니다.
- 수정 화면은 기존 제목, 메모와 카테고리를 표시하고, 사용자가 제목과 메모를 변경하거나 다른 기존 카테고리를 선택할 수 있게 해야 합니다.
- 수정 화면에서 할 일의 날짜를 변경하거나 카테고리 이름 자체를 편집할 수 없어야 합니다.
- 할 일 수정 시에도 등록과 같은 제목·메모 입력 조건과 카테고리 필수 선택 조건을 적용해야 합니다.
- 개별 할 일은 별도 확인 없이 즉시 삭제하고, 사용자가 짧은 실행 취소 메시지에서 삭제를 취소할 수 있어야 합니다.
- 오늘 날짜의 할 일 또는 연결된 카테고리가 변경되면 홈의 오늘 할 일에도 동일한 결과를 반영해야 합니다.

### 할 일 등록

- 할 일 추가 버튼을 선택하면 제목, 선택적 메모, 카테고리 선택과 완료 버튼이 있는 입력 바텀시트를 열어야 합니다.
- 바텀시트가 열리면 제목 입력란에 초점을 두고 키보드를 표시해야 합니다.
- 제목과 카테고리가 유효하게 입력되기 전에는 완료 버튼을 비활성화해야 합니다.
- 제목 또는 메모가 입력 조건을 충족하지 않으면 해당 입력란에 오류 원인과 수정 방법을 표시해야 합니다.
- 저장 중에는 완료 버튼을 처리 상태로 표시하고 중복 제출을 막아야 합니다.
- 저장에 성공하면 바텀시트를 닫고 선택 날짜의 목록을 갱신해야 합니다.
- 저장에 실패하면 입력값과 선택값을 유지하고 재시도할 수 있게 해야 합니다.
- 작성 중인 내용이 있는 바텀시트를 닫으려 하면 내용 폐기 여부를 확인해야 합니다.
- 키보드는 현재 입력란과 완료 버튼을 가리지 않아야 합니다.
- 카테고리가 하나도 없으면 할 일 등록을 막고 카테고리 생성 화면으로 이동할 수 있는 안내를 표시해야 합니다.
- 카테고리 추가·수정·순서 변경 결과는 할 일 등록과 수정 화면의 카테고리 목록에 반영해야 합니다.

카테고리 자체의 관리 동작은 [카테고리 요구사항](../category/category_requirement.md)을 따릅니다.

## 제외 범위

- 반복 할 일
- 할 일 날짜 변경과 미완료 할 일의 자동 이월
- 할 일의 카테고리 간 또는 날짜 간 드래그 이동
- 할 일 수정 화면에서의 카테고리 이름 편집
- 할 일 변경 결과의 통계 반영
- API 요청·응답 형식과 데이터베이스 스키마 정의
