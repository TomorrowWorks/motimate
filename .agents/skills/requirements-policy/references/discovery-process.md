# Requirement / Policy Discovery Process

최초 Requirement와 Policy 도출은 다음 순서로 진행한다.

`목적 → 행위자 → 정상 흐름 → 상태 → 제약 → 예외 → 경계 → 확정`

## 목적

기능이 해결하는 문제, 사용자가 할 수 있어야 하는 일, 성공 결과를 확인해 Requirement 후보를 찾는다.

## 행위자

행동 주체와 대상, 인증 여부, 사용자 상태나 역할에 따른 권한 차이를 확인한다. Requirement와 권한 관련 Policy 후보를 찾는다.

## 정상 흐름

시작 지점, 논리적 입력, 시스템 처리, 사용자에게 보이는 결과와 다음 행동을 확인한다. API DTO나 화면 컴포넌트가 아니라 제품 행동을 기준으로 한다.

## 상태

최초·중간·종료 상태와 상태 전이, 복귀 가능 여부, 종료 후 허용 행동을 확인한다. 후보 상태를 제시할 수 있지만 사용자 확인 없이 확정하지 않는다. 상태가 없는 기능도 검토 후 `별도 상태 없음`으로 정리할 수 있다.

## 제약

허용·불가 조건, 반복 가능 여부, 수량·횟수 제한, 특정 상태나 권한에 따른 제한을 확인한다. 값이 정해지지 않았다면 임의로 채우지 않는다.

## 예외

대상이 없거나 이미 처리된 경우, 동시 요청, 상반된 행동, 처리 실패 등 정상 흐름을 벗어나는 상황과 기대 동작을 확인한다.

## 경계

만료, 취소, 재시도, 삭제, 탈퇴, 연관 데이터 변경과 완료 후 수정 등 생명주기 경계의 규칙을 확인한다.

## 확정

문서 작성 전에 다음을 사용자에게 제시한다.

1. 확정 가능한 Requirement 후보
2. 사용자가 결정한 Policy 후보
3. 아직 답이 없는 결정 사항

미결정 사항을 임의로 채우지 않고 사용자 확인 후 문서를 작성한다.

## 질문 운영 원칙

- 이미 프로젝트 자료나 답변에서 확인한 내용은 다시 묻지 않는다.
- 현재 단계의 관련 질문을 2~5개 정도로 묶는다.
- 전문용어 대신 실제 서비스 상황으로 질문한다.
- 선택지는 제시할 수 있지만 결론을 대신 내리지 않는다.
- 복잡한 Domain은 중간 체크포인트에서 확정 내용과 미결정 사항을 요약한다.
