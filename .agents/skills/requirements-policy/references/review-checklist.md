# Requirement / Policy Review Checklist

## Requirement

- [ ] 사용자 행동 또는 시스템 제공 기능으로 표현했는가?
- [ ] 구현 방식이 아니라 기대 동작을 설명하는가?
- [ ] 선행 조건, 정상 흐름, 주요 예외와 완료 조건이 검증 가능한가?
- [ ] Policy의 상세 규칙을 불필요하게 중복하지 않았는가?
- [ ] 관련 Policy ID가 실제로 존재하는가?

## Policy

- [ ] 하나의 명확한 비즈니스 규칙을 표현하는가?
- [ ] 적용 조건과 예외가 명확한가?
- [ ] 임의의 숫자, 기간, 제한 또는 권한을 만들지 않았는가?
- [ ] 구현 세부사항이 섞이지 않았는가?
- [ ] 관련 Requirement ID가 실제로 존재하고 다른 Policy와 충돌하지 않는가?

## State / Lifecycle

- [ ] 필요한 상태와 상태 전이가 빠짐없이 정의되고 서로 모순되지 않는가?
- [ ] 취소, 거절, 실패, 재시도, 만료, 삭제, 탈퇴 조건을 검토했는가?

## Traceability

- [ ] Requirement와 Policy의 양방향 참조가 존재하는가?
- [ ] 삭제된 ID를 재사용하지 않았는가?
- [ ] 레거시 문서라면 사용자 동의 없이 ID 형식으로 변환하지 않았는가?

## Project consistency

- [ ] `docs/PROJECT_OVERVIEW.md`와 MVP 범위에 모순되지 않는가?
- [ ] 두 문서와 `features/README.md`의 상태와 링크가 일치하는가?
- [ ] 사용자가 요청하지 않은 기능, API, 스키마 또는 구현 결정을 추가하지 않았는가?
- [ ] 미결정 사항을 확정된 정책처럼 표현하지 않았는가?
